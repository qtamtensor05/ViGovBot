# Task Planning

Use the stated objective, constraints, known state, acceptance criteria, and
authorization boundary to divide complex work into verifiable phases. Identify
dependencies, risky or long-running operations, expected artifacts, and a
stopping condition for each phase.

Audit enough of the current repository before committing to architecture. Prefer
phases that end in observable evidence rather than activity descriptions. Update
the plan when evidence changes and distinguish planned, in-progress, verified,
skipped, and blocked work.

Skip this workflow for a typo or a straightforward one-file edit. A completed
plan is not evidence that implementation or testing occurred.
